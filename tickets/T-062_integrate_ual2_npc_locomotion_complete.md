# T-062 - Integrate UAL2 NPC locomotion

Status: Complete

## Goal

Use `Universal Animation Library 2[Standard]` to add role-appropriate NPC movement animation and complete reliable speed-driven idle, walk, and run playback for the Standard human NPC models.

## Context and evidence

- The user supplied `Universal Animation Library 2[Standard].zip` at the repository root. Its SHA-256 is `4008EA208A604773A2B2177D965F0F5D3195498B5BF838C3F5785D68E95F2A68`.
- The archive license is CC0 1.0 Universal / Public Domain Dedication and identifies Quaternius as the author.
- `UAL2_Standard.glb` and `UAL2_Standard_RM.glb` each contain 43 clips and the same 65-joint skeleton as both Standard body models.
- UAL2 Standard contains useful looping clips including `Walk_Carry_Loop`, `Zombie_Idle_Loop`, and `Zombie_Walk_Fwd_Loop`, but it contains no normal run/jog clip. This ticket must not relabel a one-shot dash or walking clip as a run.
- The repository already has the same-rig, trimmed CC0 `locomotion.glb` with `Idle_Loop`, `Walk_Loop`, and `Jog_Fwd_Loop`; `Jog_Fwd_Loop` remains the honest normal running source.
- The current shared locomotion loader is partial and the baseline suite contains eight failures in its cache/lookup contract. It stores state but does not yet provide accepted NPC playback.
- T-061 integrates `HumanCharacterVisual` into NPC lifecycle and must be accepted first.
- The working tree contains an unrelated user change in `scripts/world/lamp_field.gd`; it is outside this ticket and must remain untouched.

## Decision

Integrate UAL2 as a supplemental same-rig library rather than claiming it replaces normal running. Armed hostiles use UAL2 `Walk_Carry_Loop` at walking speed and a compatible UAL2 hostile idle selected after visual inspection (`Zombie_Idle_Loop` only if it reads as intentional hostile posture without breaking the game's tone). Civilians use the existing neutral idle/walk clips. All NPCs use the existing `Jog_Fwd_Loop` for normal running. Repair the shared playback and transition path so the user-visible result improves both role-specific movement and running even though the UAL2 Standard payload itself has no run clip.

If visual/runtime inspection shows `Zombie_Idle_Loop` is unsuitable, retain `Idle_Loop` for hostile idle and still use `Walk_Carry_Loop`; report the evidence. Do not substitute a one-shot UAL2 dash as a looping run.

## Exact implementation scope

- Import and document the minimal UAL2 Standard animation source needed by the selected role-specific clips.
- Build a process-wide cache keyed by source and exact clip name. Cache growth must remain bounded and 250 logical characters must reuse identical `Animation` resources.
- Attach or configure one animation player for the active imported body skeleton; retarget by the verified identical 65-joint names and keep animation resources shared.
- Implement deterministic state mapping with explicit tested thresholds: near-zero speed selects idle, ordinary profile movement selects walk, and running/panic speed selects `Jog_Fwd_Loop`.
- Use UAL2 `Walk_Carry_Loop` for armed hostile walking. Use neutral `Walk_Loop` for civilians. Use the chosen UAL2 hostile idle only if runtime inspection validates it; otherwise use neutral `Idle_Loop`.
- Loop locomotion clips, preserve in-place gameplay movement, and prevent root-motion tracks from changing `CharacterBody3D` position.
- Drive playback from actual horizontal NPC speed and role after T-061 activation. Reset playback, role, speed, and tier state on pool release/reuse.
- Preserve graceful failure: missing source/library/skeleton/clip must leave gameplay and scene instantiation functional with a defined status.
- Preserve the existing normal/throttled/frozen animation-tier API. Normal updates continuously; throttled changes only on its update cadence/API; frozen holds idle without advancing.
